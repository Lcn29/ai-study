# 压缩后，还能继续正确工作吗：从长日志到交接卡

一段长对话被压成“正在处理退货”。只看这句话，你知道现在要回答什么、能做什么、哪条材料还没读到，以及下一步该查哪里吗？

摘要很短，却不够继续工作。压缩要删除重复、减少占用，也要留下决定下一步的事实、约束和证据位置。**变短与还能正确接续，是两项不同的检查**。

本文对应《AI学习目录》第 11 课“压缩后，还能继续正确工作吗”，依据《32课学习设计与掌握目标》组织。读完并独立完成练习后，你应能：

1. 删除重复，仍保留目标、事实、限制、来源、待办和未解决失败。
2. 用具体新问题说明否定词与限定词丢失会怎样改变答案。
3. 写一张明确交接卡，让接手者只看卡片就能指出下一步与边界。
4. 保留重新读取原文的定位，不把摘要当成完整证据。

你只需要会读材料、核对条件，不需要会编程或搭建记忆数据库。文中的设备条款、日志、读取失败与交接卡都是教学设置，**不是实际退货制度或真实服务运行记录**。

## 先补必要概念：压缩、锚点和交接卡

**上下文**，是模型在当前处理里实际可见的信息。长任务会积累旧问题、规则、工具返回和阶段结果；如果全部继续带入，内容就会越来越多。

**压缩**，在本课指从旧内容中提取或整理接下来需要的信息，用更紧凑的表示参与后续工作。它可以选取原句、重写摘要或写成字段卡，不等于无条件删掉最早的消息。[^压缩]

**锚点**是需要特别保护的关键信息，例如用户明确说的禁止动作、决定结论的限定条件。它不是某个产品的固定字段名，而是本课对保留责任的称呼。

**交接卡**是压缩后的工作记录，说明当前任务、已知状态、证据缺口和下一步。它的好坏要用接续任务验证，不能只数有几行。

```mermaid
flowchart LR
    A["长日志与原材料"] --> B["删重复，保留条件、约束和失败"]
    B --> C["交接卡与回查定位"]
    C --> D["用新问题测试接续"]
    D -->|信息够用| E["核对新事实与证据后继续"]
    D -->|发现缺口| F["返修卡片或补读原文"]
    F --> C
```

## 一、先看一段长日志究竟包含什么

### 明确当前目标和材料范围

课程主问题是：

```text
2025-06-12提出申请，购买设备签收第10天，未拆封，
有含订单号的电子凭证，能申请退货吗？
```

任务只做材料判断，尚未授权任何外部动作。按申请日期与购买对象核对后，教学材料乙适用；签收当天计第 `0` 天。

本场景已经核对的乙条款是：

| 已核材料 | 教学原文 |
| --- | --- |
| 乙1 | 购买设备在签收后第 0—14 天、未拆封，可以申请退货。 |
| 乙2 | 凭证可以是纸质发票，或含订单号的电子凭证；聊天截图不属于上述凭证。 |

乙在 `2025-06-01` 起生效，明确替代旧购买规则；课程的租用材料丙不适用于购买退货，也不修改乙。这是当前已经确认的适用范围。

**乙3的读取状态另外保留**：上次工具返回不完整，原文尚未重新取得。本文不把其他课程中见过的内容补进这次失败记录；如果问题需要乙3，必须重新读取并核对。

### 把重复与状态分开

把课程的重复搜索、解释和失败整理成以下教学日志。条目编号只用于本篇定位，不是实际系统回执编号：

1. 用户要求回答上述主问题，只依据三份教学材料，不执行外部动作。
2. 从问题取出申请日、购买对象、第 10 天、未拆封和含订单号电子凭证。
3. 已核对申请日期与对象，确认乙适用。
4. 已取得乙1、乙2完整内容，原文见上表。
5. 按乙1、乙2判断原问题满足展示的申请条件。
6. 围绕同一材料重复搜索多次，没有取得会改变当前结论的新材料。
7. 再次重复解释原问题期限和凭证已经满足。
8. 尝试重新读取乙3，但工具返回不完整；乙3原文尚未重新取得。
9. 尚未执行任何退货申请、批准或退款。
10. 若用户改问已拆封情况，先重新取得乙3；接续前仍应检查当前事实是否改变。

第 6、7 条的大段重复说明可以合并，但第 8 条的未解决失败不能随它们一起消失。第 9 条的“未执行”也不能改写成“已处理”。

### 删除什么，保留什么？

| 内容 | 本例处理 | 理由 |
| --- | --- | --- |
| 相同条件的重复说明 | 合并成一条有来源的结论 | 不必让接手者再读相同解释 |
| 重复搜索的完整过程 | 只保留有新信息或尚未解决的结果及定位 | 次数本身不证明证据更强 |
| 目标与未授权动作 | 保留明确表述 | 决定要完成什么、不能做什么 |
| 日期、天数、对象、拆封、凭证限定 | 分项保留 | 各自决定规则适用和资格判断 |
| 已核条款与来源位置 | 保留 | 新问题可能需要回到原文 |
| 乙3不完整返回 | 保留失败和未取得状态 | 防止下一轮误认为材料齐全 |
| 下一步与待办 | 保留触发条件和操作 | 让任务能够接续 |

**重复可以删除，尚未解决的困难不能靠摘要消除**。保留失败不是让卡片显得冗长，而是防止后续建立在不存在的证据上。[^压缩]

## 二、把长日志压成一张明确的交接卡

### “正在处理退货”缺了什么？

它没有说清“处理”是问答还是执行，没有日期与适用对象，没有凭证限定，也没有乙3读取失败。接手者无法区分已知结论、未知材料与实际动作状态。

一张合格卡片应让这些责任显式可见。下面字段由本教程定义，不是某个 API 的固定结构。

```text
目标：回答原主问题；尚未授权任何外部动作。

用户事实：
申请日期=2025-06-12；对象=购买设备；签收第10天；
未拆封；含订单号的电子凭证。

硬约束：
只依据三份教学材料；不宣称退款完成。
不得把未授权动作改写为待执行动作。

已验证：
乙适用，2025-06-01起替代旧购买规则，租用材料不改变乙。
原问题按乙1、乙2满足展示的申请条件；本次没有执行申请、批准或退款。
乙2：合格凭证为纸质发票或含订单号电子凭证；聊天截图不属于上述凭证。

未解决：
教学日志第8条记录读取乙3返回不完整；乙3原文尚未重新取得。

下一步与定位：
没有新条件时，可交付原问题的有限结论。
若用户改问已拆封，先重读教学材料乙的乙3，完整取得后再判断。
若改问凭证，回查教学材料乙的乙2完整条款，包含允许项与聊天截图否定句。
不得用残缺返回作新结论的依据。
```

它比“正在处理退货”长，但保住了继续工作的条件。压缩目标是**保住下一步必要信息并去掉重复**，不是争取最短的一句话。

### 几组容易混淆的状态必须分开

| 原来区分的内容 | 危险的合并写法 | 为什么不够？ |
| --- | --- | --- |
| 申请日期；签收第几天 | “日期：10天” | 失去选择版本和判断期限的两个不同依据 |
| 满足申请条件；未执行动作 | “退货已处理” | 容易让人误以为已经办理或退款 |
| 乙1、乙2已取得；乙3未重新取得 | “乙规则已看过” | 不能说明哪条证据可以使用 |
| 含订单号电子凭证 | “电子凭证” | 丢失乙2的必要限定 |

“已验证”需要限定验证了什么；它不能替未解决材料背书，也不能把资格判断升级为执行成功。

## 三、来源定位怎样留下，才真的能回查？

### 卡片写的是导航，不是替原文作证

摘要是由其他材料提炼出来的，属于**派生材料**。它可能遗漏、改写或继承旧错误，变短并不会自动提高可信度。[^压缩]

本例的凭证回查定位可以写成：

```text
来源：教学材料乙。
适用范围：2025-06-01起的购买规则。
位置：乙2完整条款。
重点：纸质发票／含订单号电子凭证的允许项，聊天截图的否定句。
```

乙3失败的定位则是：

```text
来源目标：教学材料乙，乙3。
当前状态：原文尚未重新取得，不能用残缺返回判定。
失败记录：本篇教学日志第8条。
```

**材料身份、适用范围、条款位置和取得状态，都要可辨认**。写“详见之前”不能帮助一个没有完整历史的接手者找到证据。

### 真实工作要填真实定位

实际文档可使用真实标题、版本日期、章节、页码或系统提供的返回标识。具体位置必须从已有材料取得，不能编造文件名或把猜测的段落号当成定位。

公开博客里不需要写私有文件路径；但实际交接流程要保证接手者确实能取得相应材料。**知道要查乙3，不等于乙3已进入本轮可见上下文**。找不到或返回不完整时，继续保留缺证状态。

如果摘要与原文发生差异，应回到支持结论的原件核对，并修正派生摘要。不能因为卡片已经被重复引用，就把它当成新的独立来源。

## 四、删掉一个词，为什么能改变下一步？

### “含订单号”不能压成可有可无

原条款允许的是“含订单号的电子凭证”。如果卡片只写“乙允许电子凭证”，接手者看到一个订单号情况未知的电子凭证，就可能直接判成合格。

条件变化后的对照是：

| 当前凭证事实 | 应怎样处理？ |
| --- | --- |
| 明确含订单号的电子凭证 | 在其他条件满足时，符合乙2该凭证路径 |
| 电子凭证，订单号情况未说明 | 缺必要信息，先补充，不能确认符合乙2 |
| 仅有聊天截图 | 乙2明确排除，不因期限合格而变合格 |

**限定词决定适用条件，不能因重复或字短而删掉**。卡片可以保留完整句，也可以明确让下一步先重读完整条款；不能仅剩扩大后的允许项。

### 否定句删除，可能把禁止读成允许

删去“聊天截图不属于上述凭证”，会让接手者不知道这一排除条件。删去“没有执行退款”，会让阶段结果失去动作边界。

另一个课程教学任务是整理文章。用户约束“不能修改原始资料”应被原样保护；如果摘要只写“继续整理资料”，接手者就失去明确的只读边界。它与退货案例是两个任务，不能混成同一份授权。

**禁止、未执行、尚未取得，各自说明不同状态**：不能做、不曾做、没有证据。压缩时把它们都抹成“处理中”，后续决策就失去了依据。

## 五、用接续测试检验卡片，而不是只比字数

### 只给卡片，让接手者回答四个问题

不用展示完整旧对话，先看接手者能否说明：

1. 当前目标是什么？
2. 下一步是什么，什么时候需要先回查？
3. 不能做什么？
4. 哪条证据仍缺，应该在哪里找？

对第二节那张卡，合格接续应指出：目标是问答；原问题可给有限结论；没有外部动作授权；乙3没有重新取得，改问已拆封时先重读它。

四项任何一项说不清，就回到卡片补对应内容。**接续测试检查的是决策所需信息有没有留下**，不是接手者能否复述卡片标题。

### 换问题，暴露摘要的失真

第一种改问：“聊天截图可以吗？”

当前问题改变了凭证条件，不能机械复用旧的“含订单号电子凭证”事实。卡片保留了乙2的排除句及定位，可以据其说明这类凭证不合格；需要完整证据时回到乙2原文核对。

第二种改问：“其实已经拆封，怎么处理？”

原结论以未拆封为前提，不能沿旧事实答题。卡片明确乙3未重新取得，所以应停住对乙3处理规则的断言，先重新读取完整原文，再判断新的问题。

可以先说明“原结论针对未拆封情况，新的已拆封条件需要回查乙3，当前记录中该条原文尚未重新取得”。**不能把一次失败返回压成已经完成的读取，更不能从别的任务记忆补条文**。

第三种改问：“第 14 天、未拆封，有电子凭证，能申请吗？”

这仍沿本课 `2025-06-12`、购买设备的设定。第 `14` 天在期限内，未拆封满足乙1，但订单号情况没有说明。正确接续应指出这一缺项，继续核对乙2，而不是把旧案例的“含订单号”自动转移给新输入。

以上测试改变的是已明确写出的事实或问题范围。卡片不用保存所有可能答案，但需要保住让接手者发现变化和回查原文的线索。

## 六、恢复摘要，为什么还不等于恢复工作现场？

### 信息记录和真实环境各有自己的状态

摘要可以告诉后续读者曾经创建文件、修改数据或启动进程，但它本身不会重新创建那个文件、恢复进程，也不会撤销已发生的远程动作。

对退货任务，卡片写“未执行”只能记录当前已知状态，不能代替真实服务的对账。对文件任务，卡片写“图像路径未解析”也不会自动让图片出现。

**继续工作前，要分别核对记录与当前环境**。发现结果未知或环境变化时，先检查实际对象；不能根据旧摘要无条件重复带副作用的动作。

这里仅说明责任边界，实际权限、失败恢复和长期状态会在后续课程展开，本课不执行真实业务操作。

### 文本压缩与 KV 缓存优化作用不同

应用层摘要改变后续输入中保留的文字；模型推理里的 **KV Cache，键值缓存**，复用已经计算过的历史键和值。二者发生在不同层级，不能用同一种“压缩”笼统替代。[^压缩]

有缓存不等于可以删除决定结论的句子；卡片变短也不证明已恢复模型计算缓存。具体缓存机制留到第 26—27 课。

### 公开 compact 案例说明什么？

**Compaction，紧凑化**，常指把累积的历史整理成摘要，用更紧凑的信息继续长任务。Anthropic 的工程文章强调保留关键决策、未解决问题和细节，同时提醒过度压缩可能丢失后来才显得重要的信息。[^官方]

课程另一份 Claude Code 讲解记录了一次压缩后组装：较早历史摘要、保留的近期消息、重新载入的相关文件共同进入后续请求。因此“有了一份摘要”与“后续已经获得全部工作材料”也不是同一件事。[^案例]

该讲解没有提供对应版本号、完整抓包原件或固定提交，不能把它的消息数、附件数量或摘要模板当成所有版本的实现规范。本篇不提供产品命令、配置字段或固定压缩阈值。

## 七、合上文章，完成四个基础检查

先根据本文的教学日志、乙1—乙2和乙3失败状态作答。只用已经提供的内容，不补完整乙3。

### 检查 1：删重复，不能删掉哪几类信息？

有人把第一节十条日志压成：

```text
已看乙规则，退货已处理，继续。
```

指出至少四处信息丢失或状态夸大。哪些重复可以删除？把这份摘要修成含目标、用户事实、硬约束、已验证、未解决、下一步与定位的交接卡。

### 检查 2：用一个新题证明限定词不能丢

坏卡片写：“乙允许电子凭证。”它没有订单号限定，也没有聊天截图否定句。

分别处理“电子凭证但订单号未说明”和“仅有聊天截图”。坏卡片可能怎样误导？应保留或回查哪条内容？

再说明，把“不能修改原始资料”缩成“整理资料”为什么不合格。

### 检查 3：交接之后，第 14 天的新题怎样答？

沿本课日期与购买对象，新的事实是第 `14` 天、未拆封，电子凭证没有说明订单号。

写一小段接续记录：当前目标、下一步、禁止动作和仍缺的证据分别是什么？能否把旧案例的订单号事实继承给新输入？若已在卡片中保留乙2完整限定，是否还需要立即补读乙3？

### 检查 4：乙3读取失败和工作现场怎样接续？

接手者拿到原交接卡，用户改成“其实已经拆封”。他准备直接复用旧的允许申请结论，又说“摘要已经恢复，外部工作现场当然也恢复了”。

指出两种推断的问题。应回查哪个位置，怎样处理未取得状态？如果另一个文章整理任务卡写“图像路径未解析”，是否表示图片已恢复？

## 八、参考答案与达标标准

### 检查 1 的参考答案

坏摘要丢掉原问题目标、日期对象与凭证事实、未授权动作、乙3失败及下一步；“已看乙规则”扩大了已取得范围，“退货已处理”把资格判断混成了动作完成。

重复搜索和同一结论的反复说明可以合并。合格卡可以这样写：

```text
目标：只回答原主问题，尚未授权任何外部动作。
事实：2025-06-12申请；购买设备；签收第10天；未拆封；含订单号电子凭证。
约束：只依三份教学材料，不宣称退款完成。
已验证：乙适用；乙1期限与未拆封、乙2凭证条件均满足；未执行外部动作。
保留条件：乙2只允许纸质发票或含订单号电子凭证，聊天截图不属于上述凭证。
未解决：日志第8条的乙3返回不完整，原文尚未重新取得。
下一步：原问题可给有限回答；新问题改变条件时重新核对。
定位：凭证查教学材料乙的乙2完整条款；已拆封处理先重读乙3。
```

字段名称可以变化，但每种责任必须保留，来源定位和取得状态要清楚。

**过关点**：删掉的是重复，不是约束或失败；卡片没有夸大证据和动作状态。

### 检查 2 的答案

订单号未说明时，不能确认电子凭证满足乙2，应指出缺项；聊天截图则被乙2明确排除。这两种情况分别是信息缺失与已知不合格，不能都按泛化的“电子凭证”允许。

应恢复“纸质发票或含订单号电子凭证；聊天截图不属于上述凭证”，或者明确先重读乙2完整条款，再作结论。

“不能修改原始资料”是明确禁止；“整理资料”只写目标，没有保留只读约束。即使更短，也不能支持遵守用户要求的接续。

**过关点**：用具体变式说明失真后果，精确保留限定、否定和用户硬约束。

### 检查 3 的答案

```text
目标：按新输入判断购买退货申请条件。
已知：本课日期对象不变；第14天、未拆封，满足乙1相关条件。
缺项：电子凭证是否含订单号。
下一步：向用户确认订单号情况；凭证依据定位乙2完整条款。
禁止：不能把旧输入的含订单号事实补给新输入；未授权外部动作，不宣称退款完成。
有限结论：目前资料不足，尚不能确认符合乙2。
```

订单号事实属于原输入，不能机械继承。当前缺口是凭证信息，不是已拆封处理；如果乙2限定已经完整保留且来源可回查，不需要仅因“有一条未取得”就把乙3当成这个新题的必要证据。

**过关点**：识别新旧事实边界，精准定位当前缺项与下一步，不无条件重读无关材料。

### 检查 4 的答案

旧结论针对未拆封；新输入已经改变这个前提，不能照旧认可申请。已拆封处理需要回到教学材料乙的乙3，而交接记录显示它原文未重新取得。先补读完整原文，再据新事实判断；缺证时保留缺口，不把残缺返回或记忆中的条文补进去。

恢复摘要只恢复信息记录，不自动恢复外部文件、进程或远程动作。另一任务的图像路径未解析依然是待解决失败，需要定位实际资源与路径并核对状态，不表示图片已经恢复。

**过关点**：用来源定位继续工作，保留取得状态，并分开摘要记录与真实环境。

### 怎样判断达标？

能独立完成四题并解释理由，就覆盖本课四项基础要求。让另一位读者只看你写的卡片，能否说清目标、下一步、禁止动作和缺证，是进一步检查。

| 卡点 | 回读位置 |
| --- | --- |
| 删掉限制和失败，只剩进度一句话 | 第一、二节 |
| 认为省掉限定词只影响措辞 | 第四节的凭证与否定对照 |
| 把旧输入事实带入新问题 | 第五节的三种改问 |
| 把摘要当原文或环境快照 | 第三、六节 |

压缩提示跑通或字数下降，都不能直接当成接续合格。

## 九、可选进阶：按材料用途选择压缩方式

### 抽取、重写与结构化，各保留什么？

| 方式 | 本例可以怎样用？ | 需要另查什么？ |
| --- | --- | --- |
| 抽取原句 | 保留用户禁止动作、乙2限定及否定句 | 是否遗漏分散在其他位置的必要条件 |
| 生成摘要 | 合并重复搜索和解释 | 有没有新增事实、删掉未解决失败 |
| 结构化记录 | 写目标、事实、约束、状态和定位字段 | 字段是否够用、状态是否混淆 |

可组合使用：关键原句保真，旧过程归纳，状态写卡。结构化卡不是天然无损；没有字段容纳的信息也可能被遗漏。[^压缩]

### 热材料放当前，冷材料留下入口

接下来马上要用的事实、硬约束和已核条件进入当前上下文；详细旧日志与原材料保存在可回查的位置，需要时重新取得。

外部保存与本轮可见是两件事：材料存着，不证明模型已经看见；卡片有定位，也不证明读取成功。结构化笔记的作用是把进度和依赖保留在窗口之外，再在以后需要时提供回来。[^官方]

先保存不可丢的记录，再用摘要替换旧历史，可以减少压缩遗漏难以追查的情况。但保存动作本身需要有完成证据，不能只在摘要里写“已保存”就当作成功。

### 记录压缩验收，不只记录长度

本例可以留一份简短检查记录：

```text
目标保留：仍是问答，不是执行退款。
事实保留：日期、购买、第10天、未拆封、含订单号分别可辨。
否定与约束保留：聊天截图不属于；未授权动作；不宣称完成。
来源与失败保留：乙1/乙2已核，乙3未重新取得，定位可找。
接续问题：第14天电子凭证订单号未知；已拆封改问。
检查结果：前者指出订单号缺项；后者先回查乙3。
```

这是教学验收的预期，本文未让真实模型运行这些测试。实际使用时记录接手者真正给出的结果，哪项失败就返修哪部分卡片；不要把写了检查清单等同已经通过。

压缩程度由任务与接续表现判断，没有本课通用的固定字数、比例或保留消息数。产品如何组装摘要、近期原文与附件，要看实际版本；本节不搭建新的记忆系统。

## 下一步：保存下来的内容，还要管理身份与边界

现在你能把长日志转成交接卡，保住条件、来源、动作边界和未解决失败，并用变式问题判断它是否够用。

第 12 课“结构、隔离与可信写回”会继续讨论哪些内容可以写回，材料的身份与信任边界如何保留。压缩让历史更紧凑，不能因此把外部材料里的文字变成新的动作授权。
