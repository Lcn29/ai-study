# 第三阶段串讲：把任务说清楚，用示例定规则，按步骤核验

前两个阶段解释了模型怎样处理文字：输入经过切分、表示和上下文计算，再逐步生成输出。到了使用模型时，还有一个更直接的问题：你希望它完成的工作，究竟怎样进入这次输入？

“整理一下”“帮我处理退货”“认真想一想”，都表达了意图，但仍可能留下范围、条件和结果标准的空白。模型写出一段流畅文字，也还没有证明这项工作做对了。

第三阶段的三个小节就沿着这项任务继续展开：第 07 课先把要求写清楚，第 08 课用正确示例说明输出规则，第 09 课把多步工作的中间结果变得可检查。

它们不只是三种提示技巧。前一步为后一步确定目标与依据，后一步让前面的要求能够在实际产物上核对。沿着同一项设备规则问答走完这条过程，就能看到各方法为何需要、哪里可能失败，以及该在哪一步纠正。

本文依据《AI学习目录》第 07—09 课及《32课学习设计与掌握目标》中第三阶段要求。所有制度、日期、标签和步骤例子都属于课程教学设计，不是现实退货政策，也不是模型效果测试。本篇以连续串讲连接三个小节，不设置独立题目或答案章节。

## 一、从一个宽泛要求，走到有边界的任务

先沿用课程的三份设备规则。按**提出申请的日期**选择适用规则，签收当天计第 `0` 天。材料只有下列条款，没有未展示的特殊制度：

| 材料与时间 | 条款 | 教学原文 |
| --- | --- | --- |
| 甲：2024-12-20 发布，2025-01-01 至 2025-05-31 生效 | 甲1 | 购买设备在签收后第 0—7 天、未拆封，可以申请退货。 |
| 同上 | 甲2 | 需要纸质发票；电子订单截图不能代替纸质发票。 |
| 乙：2025-05-20 发布，2025-06-01 起生效，明确替代甲的购买规则 | 乙1 | 购买设备在签收后第 0—14 天、未拆封，可以申请退货。 |
| 同上 | 乙2 | 凭证可以是纸质发票，或含订单号的电子凭证；聊天截图不属于上述凭证。 |
| 同上 | 乙3 | 已拆封设备不能按乙1申请退货，只能转维修核验；转维修不代表已经批准退款。 |
| 丙：2025-06-10 发布并生效 | 丙1 | 租用设备应在签收后第 0—30 天归还。 |
| 同上 | 丙2 | 本规则不适用于购买设备退货，也不修改乙的购买规则。 |

主问题是：

> 2025-06-12 提出申请，购买设备签收第 10 天，未拆封，有含订单号的电子凭证，能申请退货吗？

如果只把这些内容附在“帮我处理退货”后面，“处理”仍可能包括解释规则、填写申请或实际退款。这次需要先明确：我们只做材料问答，不执行外部操作。

### 任务、材料、输出和验收，各补一项具体内容

**提示词**是本次给模型的任务说明及相关输入。表达清楚，可以让模型更明确地使用已有能力，但这段输入本身不等于训练参数，也不会自动补足材料里没有的事实。[^任务]

在主问题中，可以分别写清楚：

| 要明确的内容 | 本例怎样表达 |
| --- | --- |
| 任务 | 判断是否满足已展示的购买退货申请条件 |
| 输入材料 | 当前实际提供的甲、乙、丙完整规则及用户事实 |
| 输出契约 | 结论、逐项条件与条款编号、缺少的信息 |
| 验收 | 规则版本与对象适用，事实没有改写，条件完整，结论由对应原文支持 |

**输出契约**说明要交付什么以及怎样组织；**验收**检查交出来的内容是否满足要求。写出条款编号是输出的一部分，读回原条款确认它支持结论，才完成相应核对。

因此，课程给出的最小提示可以落成：

```text
只依据下方甲、乙、丙的完整材料，回答主问题。
按申请日期和购买／租用对象选规则，逐项核对天数、拆封状态和凭证。
输出：有限结论；对应条款和条件；资料未说明或尚缺的信息。
“可以申请”不写成“已经批准”或“退款已经完成”；不执行外部操作。

材料：实际提供上述完整规则。
问题：实际提供本次申请事实。
```

模板中的材料与问题位置，使用时需要填入完整内容。仅写“参考甲乙丙”，不等于已经把原文提供给模型。

这份表达已经有可检查的标准，却没有保证模型一定做到。之后增加的示例和步骤，都应继续服从这些标准。

### 缺项不会因为角色或语气而消失

主问题中的“未拆封”如果被删掉，乙1要求的条件就没有得到确认；乙3又说明已拆封会改变路径。应指出“缺少拆封状态”，而不是只写“信息不全”，也不能猜成“未拆封”或“已拆封”。

写“你是专家”可以说明回答视角，却没有新增这项用户事实。要求“必须给肯定答案”，也不能使缺失条件成立。

角色说明、事实依据和动作授权要分别确认：专家角色不产生条款，规则说“可申请”也不授权助手实际退款，更不证明退款完成。**清楚表达首先明确的是任务与证据边界**。

## 二、规则说清楚之后，示例让输出含义变得具体

如果直接说明任务、材料与结果要求，已经能稳定达到标准，就可以停在这个版本。没有任务示例的提示，称为**零样本提示**。

若实际发现模型把“缺信息”和“条件不合格”混在一起，或者输出标签与要求不一致，可以增加正确的输入—输出示例。这样在当前上下文中演示任务模式，称为 **Few-shot，少样本提示**。[^示例]

示例补充的是怎样表达和判断，不应把任务边界或制度条款换成另一套。

### 先规定标签，才知道示例在展示什么

课程的设备分类使用三个标签：

| 标签 | 在本教学任务中的含义 |
| --- | --- |
| 允许申请 | 已提供的必要事实符合展示的申请条件 |
| 不满足 | 已知事实中存在不符合本次购买退货条件的部分 |
| 资料不足 | 必要事实尚未确认，当前材料不足以完成对应判断 |

“不满足”只说明未满足这里展示的退货条件，不能扩大为所有服务渠道都被拒绝。“资料不足”则保留未知状态，不等于已经确认条件不合格。

例如，已明确“设备拆封”与没有说明“设备是否拆封”，应有不同记录。前者与乙3对应，后者还需要补事实。

### 四个示例各自揭示一个决定条件

以下示例统一在 2025-06-12 提出申请，对象都为购买设备：

| 示例输入 | 示例输出 | 条件依据 |
| --- | --- | --- |
| 第 10 天，未拆封，含订单号电子凭证 | 允许申请 | 乙1、乙2均满足 |
| 第 15 天，未拆封，纸质发票 | 不满足 | 超过乙1的第 0—14 天范围，凭证合格不能抵消超时 |
| 第 10 天，已拆封，纸质发票 | 不满足 | 乙3排除按乙1退货；维修核验不是退货或退款完成 |
| 第 10 天，拆封状态未提供，含订单号电子凭证 | 资料不足 | 缺少乙1、乙3判断所需的拆封事实 |

每一行都要先核对标签和条款。第 15 天如果被错误标成“允许申请”，格式即使很整齐，仍然是在给出错误演示。

四例也不是四条新的制度。它们是同一组制度在不同事实条件下的应用，让正常路径、超时、已拆封和缺项都变得可观察。

### 未见组合，仍然要逐条判断

现在遇到“第 14 天、未拆封、聊天截图”，共同前提仍是 2025-06-12 申请和购买设备。

第 14 天在乙1范围内，未拆封也符合条件，但是聊天截图被乙2排除。因此这项已知凭证不合格，标签为“不满足”。不能因为它与正常示例在天数和状态上相近，就选“允许申请”。

再把凭证只写成“电子凭证”。这句话没有确认是否含订单号。在其他必要条件都满足、没有另一个已知失败条件的这个变式里，应指出订单号信息缺失，不能直接标成允许。

这里真正需要保持的是**标签与决定条件的对应关系**。示例提示了模式，新输入仍要对照规则；既不能按外观相似选答案，也不能用合格的一项抵消不合格的一项。

### 加了示例，改变的是当前输入

少样本将示例作为本次上下文的一部分，没有自动进行梯度更新或训练参数，也不自动建立长期记忆。

如果应用以后仍把这些示例带入输入，它们还可以继续影响后续调用；如果不再提供，就不能仅凭“以前给过”认定当前模型已经获得这些材料。

示例多也不保证效果持续提高。是否需要、选几条、如何排列，应根据当前任务的具体失败和核验结果决定。**正确、相关且能说明边界，比盲目增加示例数量更直接**。[^示例]

## 三、从示范答案继续到可检查的中间结果

有了任务和示例，主问题仍然包含几种依赖：需要准确提取事实，按日期与对象选制度，然后核对条件，最后形成有限结论。

第 09 课把这段过程展开。目的不是生成很长的推理文字，而是确定哪些中间结果必须正确，后续才能继续。[^步骤]

沿着同一个主问题，四步可以具体写成：

| 步骤 | 接收什么 | 交出什么 | 进入下一步前怎样核对 |
| --- | --- | --- | --- |
| 1. 提取事实 | 用户原问题 | 申请日、购买对象、第 10 天、未拆封、含订单号电子凭证 | 每项能回到原问题，缺失项保持缺失 |
| 2. 选择规则 | 日期、对象、三份规则 | 乙适用；甲不在当前生效期，丙不适用于购买退货 | 保留日期说明、乙替代甲和丙不修改乙的依据 |
| 3. 逐项判断 | 已核对事实、乙1和乙2 | 天数、拆封和凭证分别满足 | 各项事实与原条款对应，不增加外部制度 |
| 4. 形成回答 | 已确认判断及来源 | 可以申请；引用乙1、乙2；本流程没有执行退货或退款 | 结论没有越过条件和真实执行状态 |

这张表连接了前两节：第 07 课的材料边界、输出与验收，成为各步检查依据；第 08 课的标签语义，帮助表达不同条件下的结果。

**每一步交出的东西，都应能回到它的输入或依据上核对**。只把中间结果排成表格，或让程序成功解析它，还不足以证明内容正确。

### 沿着主问题走完一次

第一步确认申请日为 2025-06-12，设备是购买的，签收第 10 天，未拆封，并且电子凭证含订单号。

第二步用申请日期选生效规则。乙从 2025-06-01 起替代甲，丙只负责租用归还，因此不能把丙的 30 天带进当前购买退货结论。

第三步分别核对：`10` 在第 `0—14` 天范围内，未拆封满足乙1，含订单号电子凭证满足乙2。

第四步形成回答：

> 按乙1、乙2，已给定的事实符合教学材料中的退货申请条件，可以申请。本次只做规则问答，没有执行退货或退款；材料也没有提供审批或退款完成的结果。

这段文字不需要展示全部内部计算，就已经提供了可核验的事实、条款、条件和结论强度。

## 四、同样四步，可以在一次调用或多次调用里完成

刚才四步是工作的逻辑步骤，还没有规定必须用几次模型调用。“步骤数”和“调用数”需要分开。

**CoT，思维链提示**可以在一次调用中组织解题步骤。**链式提示**则由应用或工作流安排多次调用，把一份中间结果检查后传给下一次。两者可以结合，并非互相排斥。[^步骤]

```mermaid
flowchart TD
    subgraph A["一次调用的教学安排"]
        A1["提取事实 → 选择规则 → 条件核对 → 回答"]
    end
    subgraph B["四次调用的教学安排"]
        B1["调用1：事实表"] --> C1["对照原问题核验"]
        C1 --> B2["调用2：适用规则"]
        B2 --> C2["核验版本与对象"]
        C2 --> B3["调用3：逐项判断"]
        B3 --> C3["核验条款与事实对应"]
        C3 --> B4["调用4：有限回答"]
        B4 --> C4["核验结论、引用和执行状态"]
    end
```

上面的分法是教学安排，不是所有实现必须拆成四次。一次调用也可以交付事实表、条款和结果，供外部检查；多次调用则让流程有机会在每一步后停止、返修或替换局部处理。

拆分会增加调用和中间状态的准备、传递与检查，串行推进还会增加等待。它的价值在于能定位并处理需要检查的依赖，不是调用越多就越准确。

### 外显产物能够验收，隐藏推理无需披露

可见的步骤文字是模型给出的输出，不是内部计算的完整、必然忠实的记录。解释流畅、理由详细，仍可能与原文或最终结论冲突。

对于已经具备内部推理能力的模型，具体提示方式应遵循所用模型的指导。OpenAI 的推理提示文档建议直接说明目标和约束，不必强制索取完整思维链；这项说明有对应模型范围，不是所有模型提示策略都相同。[^推理提示]

本例可以要求事实表、条款引用、简短理由和条件判断。这些产物足以逐项对照资料，不需要要求模型公开隐藏的内部思考。

**核验依据是原文、计算和实际结果，而不是推理文字写得多长**。

## 五、最早的一处偏差，会沿着后续步骤传播

把主问题只改一项：凭证从“含订单号的电子凭证”换成“聊天截图”，其他事实保持不变。

正确的第一步应该保留“聊天截图”。随后，乙2明确排除这类凭证，结论为不满足展示的购买退货条件。

现在人为构造一条错误轨迹：

| 步骤 | 错误轨迹中的结果 | 实际问题 |
| --- | --- | --- |
| 提取事实 | 把聊天截图写成含订单号电子凭证 | 原始事实已被改写，偏差从这里开始 |
| 选择规则 | 选择乙 | 版本与对象选择可以仍然正确 |
| 条件核对 | 按错误的电子凭证信息判断满足乙2 | 后续采用了错误输入，形式上对照条款也不能挽回 |
| 形成回答 | 可以申请 | 最终结论建立在已被替换的事实之上 |

如果只看最后一段，它可能引用乙1、乙2，逻辑也写得整齐。但回到事实表，就能看到“聊天截图”在哪里消失了。

应该在第一步核验时停住，纠正凭证类型，再让后续步骤使用正确结果。多次调用本身不会自动纠错；没有检查的传递，也会把同一个偏差送进下一步。

另一种错误是四步条件全部判断正确，却把“可以申请”写成“已经退款”。这次最早偏差在第四步的结论与执行状态，不需要把整个问题都归为检索或规则选择错误。

**定位最早偏差，才能选择对应的修复位置**。少样本可以展示边界，链式提示可以插入核验点，但实际错误究竟在哪，还要由输入、产物与来源记录证明。

## 六、多次选答，为什么也不能替代证据？

如果同一个问题的结果不稳定，还可能采用 **Self-Consistency，自我一致性**：对同一提示采样多条路径，汇总最终答案，选择较一致的结果。它主要处理多次生成后的选答问题，不是前面四步之间的串行分工。[^采样]

将这几个方法放在同一条任务上，就能分清职责：

| 方法 | 本次主要改变什么 | 仍需核验什么 |
| --- | --- | --- |
| 明确任务 | 指定材料、目标、输出和边界 | 答案是否满足这些要求 |
| 少样本 | 展示正确输入与输出模式 | 标签、条件和新组合是否正确 |
| CoT 或可检查步骤 | 在一次调用中组织必要的解题产物 | 产物与原文、答案是否一致 |
| 链式提示 | 用多次调用安排步骤与结果传递 | 每步输入、输出、来源和停止条件 |
| 自我一致性 | 多次采样后汇总、选答 | 答案规则、共同错误与外部证据 |

### 一致的五次答案，可以重复同一个版本错误

课程给出的教学情形是：五次输出都采用已经失效的甲规则，都说“超过 7 天，不能申请”。五份答案一致，使用的却是同一项错误依据。

主问题发生在乙生效之后。再加一次投票，也不会让甲恢复适用，更不会产生乙1、乙2的新证据。

独立调用与随机采样不保证知识错误相互独立。多份回答来自同一底层材料错误，就可能一起错。**多次一致是选答信号，不是多份独立事实来源**。

如果采用自我一致性，还要规定答案怎样归一化、怎样计票，以及格式无效、平票或缺证时怎样处理。例如本例“允许申请”和“符合乙规则，可以申请”可以在明确的标签定义下归为同类，但“可以申请”不能与“已退款”归成同一个完成状态。

原论文在相应任务与配置中报告了效果，不能据此保证当前业务也会提高同样幅度。采样也有计算成本，投票后仍需回到适用条款和用户事实验证。[^采样]

## 七、回到同一任务，只增加能够解决具体问题的机制

这时，第三阶段三个小节已经接在一起。

从“帮我处理退货”开始，第 07 课先确定只做规则问答，实际提供材料，要求有限结论、条件和引用，并准备验收标准。缺拆封状态时指出具体缺项，角色话术不替代事实，规则允许申请不替代执行授权。

当标签或格式含义需要进一步示范时，第 08 课用正常、超时、已拆封和缺项的正确示例说明边界。新出现的第 14 天聊天截图，仍要按乙2判断；示例影响当前上下文，不自动改变参数或长期保存规则。

如果工作包含多步依赖，第 09 课让事实、适用规则、条件判断和回答都有可核验产物。根据任务决定在一次调用中完成，还是分成多次调用；发现聊天截图被改写，就回到最早的事实提取修复，而不是用更长解释掩盖它。

这条过程可以保留为：

> 先明确要求和证据，再用正确示例说明规则；把需要核对的依赖拆成产物，在继续传递前检查；最后仍以原文、条件和实际状态验收结论。

几种具体失败，对应的优先处理也就更清楚：

| 已发现的偏差 | 先修复哪里 |
| --- | --- |
| “处理”含义不清，问答与执行混在一起 | 明确任务与授权范围 |
| 把资料不足当成不满足 | 定义标签，增加经过核对的缺项示例 |
| 把聊天截图提取成含订单号电子凭证 | 核对事实提取，纠正后再传递 |
| 凭证规则根本没有提供 | 补齐来源，不靠示例数量或调用次数补造 |
| 条件正确，却声称已退款 | 检查结论强度与真实执行状态 |
| 五次都使用过期规则 | 核对版本，投票不能解决共同来源错误 |

表达、示例和拆分分别改善不同位置。没有发现对应问题时，不必把这些方法全部叠上去；改动之后，要用同一任务与边界条件重新核对，才能知道它是否真正解决了问题。

接下来的第四阶段会进一步检查这些材料、示例和中间结果有没有实际进入本轮上下文，历史过长时怎样保留工作状态，以及资料内容为何不能自行变成授权。第三阶段先留下明确的任务与可检查产物，后续才能管理它们的输入、保存和使用。
