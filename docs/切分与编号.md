# 切分与编号：从文字到 Token ID，手算一次 BPE

我们给模型输入“猫吃鱼”，看到的是三个汉字。这些文字怎样变成模型可以接收的输入？

其中一个关键步骤是：**按照规则把文字切成若干单元，再把这些单元换成词表中的整数编号。** 执行这项工作的工具叫 **Tokenizer，分词器**。[1]

本文先用一个中文例子分清“单元”和“编号”，再亲手建立一套 BPE 切分规则，最后用它处理新输入。读完后，你应当能够：

- 解释 Token、词表和 Token ID 的关系。
- 手算 BPE 的相邻对统计与合并，理解它为什么这样做。
- 用给定规则完成编码和解码，并说明 Token 数为什么不等于字数。

全文不需要编程基础。文中的切分、词频和编号均为明确约定的教学设置，可以直接用纸笔复算。

## 1. 从“猫吃鱼”认识四个对象

先约定一个最简单的教学分词器：只处理“猫”“吃”“鱼”这三个字，每个字切成一个单元，编号如下。

| 单元 | 教学编号 |
| --- | ---: |
| 猫 | 0 |
| 吃 | 1 |
| 鱼 | 2 |

于是，“猫吃鱼”经过两步转换：

```text
猫吃鱼
    ↓ 按规则切分
[猫] [吃] [鱼]
    ↓ 查询对应编号
[0, 1, 2]
```

这张图里包含四个需要分清的对象：

| 名称 | 含义 | 在本例中是什么 |
| --- | --- | --- |
| Tokenizer，分词器 | 执行切分与编码的工具 | 按字切分，再查询上面的表 |
| Token，词元 | 切分后可以单独编号的单元 | “猫”“吃”“鱼” |
| Vocabulary，词表 | 保存可用单元及其编号的对应关系 | 上面的三行对应表 |
| Token ID，词元编号 | 单元在这套词表中的整数编号 | 0、1、2 |

**把文字转换成 Token ID 序列，叫编码；从编号恢复文字，叫解码。**[1]

编号可以理解成查表时使用的门牌号。“鱼”的编号比“猫”大，只表示它们占据不同的表项，数字大小不表示重要性，编号差值也不表示含义距离。顺序则有作用：同一套教学规则把“鱼吃猫”编码为 `[2, 1, 0]`。

这套编号只属于本例。换一套词表，同一个整数就需要按那套词表重新解释。[1] 模型接收编号后，还会通过 Embedding（嵌入）等后续步骤，把它们转换成参与计算的数字表示。本文聚焦在此前的切分与编号过程。

查编号已经很直观了。接下来要解决的是：**为什么采用这样的切分规则？每个字都切成一个 Token，是否总是合适？**

## 2. 怎样切：整词、字符与子词

下面用英文单词 `unpredictable` 对比三种切分思路。这里展示的是教学切法。

| 切分方式 | 示例结果 | Token 数 |
| --- | --- | ---: |
| 整词切分 | `[unpredictable]` | 1 |
| 字符切分 | `[u] [n] [p] [r] [e] [d] [i] [c] [t] [a] [b] [l] [e]` | 13 |
| 子词切分 | `[un] [predict] [able]` | 3 |

### 整词切分：序列短，但需要收录完整单词

整词切分把完整单词作为单元。词表已经收录 `unpredictable` 时，一个编号就能表示它。

问题在于，语言不断出现新词，还存在时态、单复数和派生形式。遇到没有收录的词，也就是 **OOV（词表之外的词）**，一些方案会用 `[UNK]` 这个未知标记代替。不同陌生词都变成同一个标记后，它们原来的区别就丢失了。[1]

扩大词表可以收录更多词，但也增加了需要保存的表项。

### 字符切分：小单元可以复用，但序列变长

字符切分把这个英文单词拆成 13 个字母。只要这些字母都在基础词表里，即使完整单词从未出现过，也能逐个表示出来。

它的代价是：同一个输入变成了更长的序列，模型需要处理更多位置，并从这些小单元中学习组合关系。[1]

### 子词切分：让常见组合成为较大的单元

**Subword tokenization，子词切分**，让词表保存可以复用的片段。常见组合可以用较大的单元表示，其他词则由已有的小单元组合表示。[1][2]

上面的 `[un] [predict] [able]` 展示了这种思路，但实际结果不保证恰好对应词根、前缀或后缀。“子词”也不要求每个单元都小于完整单词；完整词同样可以成为一个 Token。

现在问题变得更具体了：**哪些相邻的小单元值得合成一个大单元？**

**BPE（Byte Pair Encoding，字节对编码）**提供了一种做法：统计相邻单元的出现次数，逐轮合并高频组合，建立词表和合并规则。[2][3]

因此，Subword 是一种切分思路，BPE 是实现它的一种算法；WordPiece、Unigram 等也是子词分词算法。下面只展开 BPE。

## 3. 手算 BPE：两轮合并怎样建立规则

BPE 最初用于数据压缩，后来被用于子词分词。用于分词时，可以从字符开始，也有从字节开始的版本。本节采用字符作为基础单元，方便直接看清每一次合并。[2][3]

### 3.1 准备基础符号和训练材料

从这一节开始，我们使用一套独立的字母教学词表，与前面的中文词表分开。基础符号有五个：

```text
a、b、c、d、·
```

其中 `·` 是词尾标记，表示一个词到这里结束。它不是输入中的真实标点。我们逐词处理，统计和合并都在各词内部进行。

训练材料也叫**语料**。本例只有两种词：

| 训练词 | 频次 | 初始拆分 |
| --- | ---: | --- |
| ab | 2 | `[a] [b] [·]` |
| abc | 1 | `[a] [b] [c] [·]` |

频次表示这个词出现了几次，所以整份材料相当于 `ab`、`ab`、`abc` 三次出现。`d` 虽然没有出现在训练材料中，但已经预先放入基础符号表，后面会用它检验新词的处理。

本例约定只进行两轮合并。真实训练也需要停止条件，例如达到目标词表大小。[3]

### 3.2 第一轮：统计并合并最高频的相邻对

在 `[a] [b] [c] [·]` 中，相邻对是 `(a,b)`、`(b,c)`、`(c,·)`。`a` 与 `c` 中间隔着 `b`，所以 `(a,c)` 不算相邻。

统计整份材料时，需要计入词频：`ab` 出现两次，它的每一对相邻单元各贡献 2 次；`abc` 出现一次，各贡献 1 次。

| 相邻对 | 来自 ab 的次数 | 来自 abc 的次数 | 总次数 |
| --- | ---: | ---: | ---: |
| (a,b) | 2 | 1 | 3 |
| (b,·) | 2 | 0 | 2 |
| (b,c) | 0 | 1 | 1 |
| (c,·) | 0 | 1 | 1 |

最高频的是 `(a,b)`，因此建立第一条合并规则：

```text
规则 1：a + b → ab
```

这里的 `+` 表示把相邻的两个单元拼成一个新单元。应用这条规则后：

| 训练词 | 合并前 | 第一轮合并后 |
| --- | --- | --- |
| ab | `[a] [b] [·]` | `[ab] [·]` |
| abc | `[a] [b] [c] [·]` | `[ab] [c] [·]` |

词表新增 `ab`，原有的基础单元仍然保留。

### 3.3 第二轮：根据新序列重新统计

第一次合并改变了相邻关系。现在的基本对象已经包括 `ab`，所以需要重新计数：

| 当前相邻对 | 来自 ab 的次数 | 来自 abc 的次数 | 总次数 |
| --- | ---: | ---: | ---: |
| (ab,·) | 2 | 0 | 2 |
| (ab,c) | 0 | 1 | 1 |
| (c,·) | 0 | 1 | 1 |

最高频的是 `(ab,·)`，建立第二条规则：

```text
规则 2：ab + · → ab·
```

`ab·` 是包含词尾标记的**一个单元**。合并结果如下：

| 训练词 | 第一轮合并后 | 第二轮合并后 |
| --- | --- | --- |
| ab | `[ab] [·]` | `[ab·]` |
| abc | `[ab] [c] [·]` | `[ab] [c] [·]` |

第二条规则没有改变 `abc`，因为其中的 `ab` 与 `·` 被 `c` 隔开，并不相邻。

至此，我们完成了 BPE 的核心训练循环：**统计当前相邻对 → 合并最高频组合 → 更新序列 → 重新统计。**[3]

### 3.4 合并究竟带来了什么收益

把整份训练材料的 Token 数加起来，就能看见变化。这里需要乘上词频，并计入词尾标记：

| 阶段 | 词表单元数 | 整份训练材料的 Token 总数 |
| --- | ---: | ---: |
| 初始状态 | 5 | `2 × 3 + 1 × 4 = 10` |
| 第一轮合并后 | 6 | `2 × 2 + 1 × 3 = 7` |
| 第二轮合并后 | 7 | `2 × 1 + 1 × 3 = 5` |

**词表增加两个单元后，表示同一份材料所需的 Token 从 10 个减少到了 5 个。**

第一轮的 `(a,b)` 出现 3 次，每处从两个单元变成一个单元，因此总数减少 3；第二轮的 `(ab,·)` 出现 2 次，因此再减少 2。这让我们看到合并高频组合的直接作用：把反复出现的多个小单元，收进一个可复用的大单元里。

词表大小与输入序列长度也由此区分开了：前者是可用单元的种类数，后者是表示具体文本需要多少个单元。本例词表变大，训练材料的表示序列变短；实际设计需要在词表规模与序列长度之间取舍。

## 4. 处理新词：使用固定规则，再查编号

### 4.1 先分清训练与使用

训练完成后，我们保存的是**词表和有优先顺序的合并规则**：

| 优先顺序 | 要合并的相邻单元 | 新单元 |
| --- | --- | --- |
| 1 | a、b | ab |
| 2 | ab、· | ab· |

| 阶段 | 做什么 | 得到什么 |
| --- | --- | --- |
| 分词器训练 | 根据材料中的频次学习合并 | 词表与合并规则 |
| 分词器使用 | 用固定规则处理输入 | 本次输入的 Token 和编号 |

使用时不再根据新输入的频次重新训练。分词器训练也不同于语言模型训练：前者建立文字的表示规则，后者学习模型的参数。[1][3]

### 4.2 把新词 abd 编成编号

先给最终词表约定教学编号：

| 单元 | Token ID | 来源 |
| --- | ---: | --- |
| a | 0 | 基础符号 |
| b | 1 | 基础符号 |
| c | 2 | 基础符号 |
| d | 3 | 预先保留的基础符号 |
| · | 4 | 词尾标记 |
| ab | 5 | 第一轮合并得到 |
| ab· | 6 | 第二轮合并得到 |

`abd` 没有出现在训练材料里，但它的每个字母都在基础表中。按照约定拆分、添加词尾标记，然后应用规则：

```text
abd
    ↓ 拆成基础符号，添加词尾标记
[a] [b] [d] [·]
    ↓ 规则 1：a 与 b 相邻，合并
[ab] [d] [·]
    ↓ 规则 2：ab 与 · 不相邻，保持原样
[ab] [d] [·]
    ↓ 查询词表
[5, 3, 4]
```

这里没有 `ab + d → abd` 这条规则，因此分词器不会因为输入了一个新词，就临时把它加进词表。

对照训练材料中的两个词：

| 输入 | 最终片段 | Token ID 序列 | Token 数 |
| --- | --- | --- | ---: |
| ab | `[ab·]` | `[6]` | 1 |
| abc | `[ab] [c] [·]` | `[5, 2, 4]` | 3 |
| abd | `[ab] [d] [·]` | `[5, 3, 4]` | 3 |

完整词 `ab` 可以表示成一个 Token，`abc` 和 `abd` 则由较小单元组合表示。这就是子词切分在本例中的具体表现。

表中的词尾标记参与计数：独立的 `[·]` 算一个 Token，合并在 `[ab·]` 中时，整个 `[ab·]` 算一个 Token。另外，**规则的优先顺序与 Token ID 分属两件事**：前者决定怎样合并，后者用于查表。

## 5. 解码：怎样从编号恢复文字

编码得到 `[5, 3, 4]` 后，解码先按同一张词表查询：`5` 对应 `ab`，`3` 对应 `d`，`4` 对应 `·`。

```text
[5, 3, 4]
    ↓ 按词表取回单元
[ab] [d] [·]
    ↓ 按顺序拼接
abd·
    ↓ 按本例约定移除末尾的词尾标记
abd
```

解码不需要把两轮合并倒着执行。词表已经记录了每个编号对应的完整单元，直接查回、拼接并处理词尾标记即可。例如 `[6]` 查回的是 `ab·`，处理词尾后得到 `ab`。

这套教学规则没有改写输入中的字母，所以能够恢复原词。真实分词器还会涉及其他处理，下面集中说明这些差异。

## 6. 从教学例子到真实分词器

### 6.1 基础单元决定能表示哪些输入

`abd` 能被编码，是因为 `d` 已经在基础表里。如果输入 `abe`，这套表里没有 `e`，也没有定义未知字符的处理方式，就无法给出完整的有效编号序列。

真实方案需要处理这样的覆盖问题。字节级 BPE 就使用字节作为基础单元：文字先按字符编码转换为字节，再在字节序列上进行处理。使用完整字节表时，可以覆盖该字符编码产生的字节序列。[3]

字符与字节是不同层次的单位。一个字符可以由多个字节表示，因此字节级分词的 Token 边界甚至可以落在一个字符内部。Token 也可以包含多个字符、标点或空格，不能把它直接等同于一个字或一个单词。[1][3]

### 6.2 切分之外，还存在预处理和特殊标记

真实分词器可以先规范化文本或进行预分词，再应用子词算法。[3] 例如，如果前面的步骤把大小写统一了，仅凭后面的编号就不能恢复输入原有的大小写。

另外，真实系统可以约定结束标记等特殊 Token。本文的 `·` 只表示教学词尾，与模型回答结束的标记分属不同约定。

因此，讨论一套分词器时，需要同时看它的预处理、基础单元、切分规则、词表和解码处理。

### 6.3 实际 Token 数应使用对应分词器检查

文中的 `ab` 有两个字母，却得到一个 Token；`abc` 有三个字母，得到三个 Token。数量取决于切分规则和标记约定。

对于真实文本，还要考虑语言、空格、标点和预处理。**同一段文字换一套分词器，Token 的边界、数量和编号都需要重新确认。**[1]

你可以在 [OpenAI Tokenizer](https://platform.openai.com/tokenizer) 中观察真实文本的结果。记录时，把所用分词器或编码方案的名称、完整输入和输出编号一起保存；比较两个结果时，先确认输入中的空格和换行也相同。本文的教学编号不用于对照工具输出。

这里讨论的是文本经过分词后的数量。完整接口请求还涉及消息格式等信息，实际用量应查看对应接口返回的统计；单独对可见文字分词，不能替代完整请求的计量。[4]

## 7. 自己做一次：三个检验理解的问题

以下计算沿用第 3、4 节的字母词表和两条规则。先独立完成，再展开答案。

### 练习 1：解释“词表变大，序列变短”

为什么第一轮合并后，词表单元数从 5 增加到 6，整份训练材料的 Token 总数却从 10 减少到 7？Token ID 的大小参与了这个决定吗？

<details>
<summary>查看参考答案</summary>

词表新增了一个可用单元 `ab`，所以种类数增加 1。整份材料中有三处 `(a,b)`，每处从两个 Token 合成一个 Token，所以总数减少 3。

词表单元数统计“有多少种可用单元”，输入的 Token 数统计“这份文本用了多少个单元”，二者不是同一个量。

Token ID 不参与最高频相邻对的选择。训练依据相邻对频次建立规则；使用时依据规则优先顺序合并，最后再查编号。

</details>

### 练习 2：处理新输入 abab，再把它解码

写出 `abab` 的最终片段和编号。第二条规则作用于哪里？解码需要重新执行合并规则吗？

<details>
<summary>查看逐步推导</summary>

```text
abab
    ↓ 拆分并添加词尾标记
[a] [b] [a] [b] [·]
    ↓ 规则 1：两处 a、b 分别合并
[ab] [ab] [·]
    ↓ 规则 2：最后一个 ab 与 · 相邻
[ab] [ab·]
    ↓ 查词表
[5, 6]
```

第二条规则只作用于末尾的 `ab` 与 `·`。第一处 `ab` 和 `·` 之间还隔着另一个单元，不能跨过去合并。

解码时查表取回 `ab` 和 `ab·`，拼接得到 `abab·`，移除末尾标记后恢复 `abab`。不需要重新执行合并规则。

</details>

### 练习 3：为什么 abe 无法得到完整编号

有人说：“既然 BPE 能处理训练材料中没出现过的新词，`abe` 也一定能直接编码。”这句话遗漏了什么条件？

<details>
<summary>查看参考答案</summary>

它遗漏了“输入需要能用已有基础单元表示”这个条件。

本例的基础表是 `a、b、c、d、·`，没有 `e`，也没有定义未知字符的处理策略。因此，虽然 `a` 与 `b` 符合第一条合并规则，仍无法为整个 `abe` 给出有效编号序列。

`abd` 能编码，依靠的是基础表中已有 `d`；新词可以组合表示，并不表示任何未收录的基础字符都会自动获得编号。

</details>

## 8. 把整条流程连起来

现在可以把本文的两个阶段放在一张图里：

```text
训练阶段：训练材料 → 统计与合并 → 词表和有序合并规则
                                      ↓ 供使用阶段调用
使用阶段：输入文字 → 按规则切分 → Token 序列 → 查表 → Token ID 序列
                                                        ↓
解码阶段：恢复文字 ← 按约定处理标记并拼接 ← 按同一词表取回单元
```

在这套教学规则下，你已经能独立推导 `abab → [5, 6] → abab`。其中，切分决定使用哪些单元，词表决定它们对应哪些编号，解码负责按约定恢复文字。

模型后续还会把编号映射为嵌入向量，再进行上下文计算。继续学习 Embedding 时，可以带着一个问题往下走：既然 Token ID 只是查表编号，编号对应的那组数字又是怎样学出来的？
