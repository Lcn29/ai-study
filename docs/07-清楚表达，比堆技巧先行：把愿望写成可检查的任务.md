# 清楚表达，比堆技巧先行：把愿望写成可检查的任务

你把几段材料发给模型，再加一句“整理一下”。模型返回了一篇通顺的总结，但你读完发现：它没有保留限制条件，也没有说明每条结论来自哪里。

你想要的是“能按原文核对的整理结果”，而输入只说了一个宽泛动作。这个差距，就是第 07 课先要处理的问题。

模型处理一段提示时，会利用已有能力生成回答。提示词可以让它知道当前任务、使用哪些材料、怎样组织输出；这些输入本身不等于更新模型参数，也不能自动补齐没有提供的事实。[^提示]

本篇对应《AI学习目录》第 07 课“清楚表达，比堆技巧先行”。读完并完成练习后，你应能：

1. 分别说明任务、输入材料、输出和验收是什么。
2. 把“整理一下”改写成有材料边界、可检查结论和出处的要求。
3. 指出缺少的具体必要信息，而不是猜一个答案。
4. 区分角色说明、事实依据与真实动作授权。

你只需要能够阅读材料、比较条件，不必先掌握 Transformer 的数学细节。本文的甲、乙、丙设备规则、日期和问题均来自课程教学设计，不是现实退货制度或实际业务建议。

## 一、先把“想做什么”拆成四个可以回答的问题

**提示词**是本次给模型的任务说明及相关输入。“整理一下”也是提示，只是还没有把要求说完整。

假设我们想让模型整理三份规则，下面四个问题可以帮助我们把意图落到具体内容上：

| 问题 | 在本次任务里要说明什么 | 一个明确的表达 |
| --- | --- | --- |
| 做什么？ | 任务目标 | 整理三份规则的主要结论，保留适用条件 |
| 根据什么做？ | 输入材料及范围 | 只依据下面给出的甲、乙、丙，不补写外部制度 |
| 交付什么？ | 输出内容与组织方式 | 三条结论，每条注明条件和来源条款 |
| 怎样算合格？ | 验收标准 | 每条结论都有支持它的原文，条件没有被删，缺少的信息如实说明 |

这里的四个问题是本课检查任务表达的视角，方便把宽泛愿望转成别人能理解、能核对的工作要求。简单任务不必机械地写成四段；相关要求已经说清楚，就不需要再增加形式。[^提示]

### 输出与验收，有什么区别？

“写三条”“用表格”“先给结论”，说明结果怎样呈现。把输出必须包含什么、怎样组织写清楚，可以称为**输出契约**。

**验收**则是按照事先说明的标准检查结果。三条结论确实写出来了，只能证明数量符合格式；还要逐条核对来源、条件和结论强度，才能知道内容是否合格。

例如，要求每条附一个条款编号，模型写出了“乙1”，仍需要检查乙1实际说了什么。编号格式正确，不代表条款能够支持那条结论。

因此，**输出要求告诉模型交什么，验收标准告诉我们怎样检查它**。

```mermaid
flowchart LR
    A["明确任务：要完成什么"] --> B["指定材料：用哪些依据"]
    B --> C["规定输出：交付哪些内容"]
    C --> D["验收结果：逐项核对来源和条件"]
```

下面用同一组教学材料，把这四个问题实际写出来。

## 二、把“整理一下”补成一条可复用的要求

### 先读完整材料，再决定怎样处理

课程给了三份设备规则。用**提出申请的日期**选择适用规则，签收当天计第 `0` 天。材料只有下表条款，没有未展示的附加制度。[^课程]

| 材料及时间 | 条款 | 教学原文 |
| --- | --- | --- |
| 甲：2024-12-20 发布，2025-01-01 至 2025-05-31 生效 | 甲1 | 购买设备在签收后第 0—7 天、未拆封，可以申请退货。 |
| 同上 | 甲2 | 需要纸质发票；电子订单截图不能代替纸质发票。 |
| 乙：2025-05-20 发布，2025-06-01 起生效，明确替代甲的购买规则 | 乙1 | 购买设备在签收后第 0—14 天、未拆封，可以申请退货。 |
| 同上 | 乙2 | 凭证可以是纸质发票，或含订单号的电子凭证；聊天截图不属于上述凭证。 |
| 同上 | 乙3 | 已拆封设备不能按乙1申请退货，只能转维修核验；转维修不代表已经批准退款。 |
| 丙：2025-06-10 发布并生效 | 丙1 | 租用设备应在签收后第 0—30 天归还。 |
| 同上 | 丙2 | 本规则不适用于购买设备退货，也不修改乙的购买规则。 |

这些原文已经能支持一些具体整理结果，但“整理一下”没有说明读者希望保留哪些内容。

如果只写“甲是旧规则，乙是新规则，丙时间更长”，看起来很简洁，却删掉了购买与租用、申请日期、拆封和凭证等决定结论的条件。

### 一步步补齐，为什么每项都有用？

先写材料边界：

```text
只依据下面的甲、乙、丙三份材料进行整理。
```

这说明当前结果应由哪些文本支持，防止把任务悄悄变成“根据常识解释真实退货政策”。边界必须与任务一致；如果任务需要外部资料，应明确允许使用哪些来源，再取得它们。

再写清保留什么：

```text
列出三条主要结论。
每条保留适用日期、对象和必要条件，并注明来源条款。
```

这样，整理结果不只是压短字数，还要把决定含义的条件带过去。

最后写缺项处理和验收：

```text
材料没有的信息写“资料未说明”。
检查每条结论是否被所列条款支持，不把“可以申请”写成“已经退款”。
```

合在一起，一条适合本次材料的教学提示就是：

```text
请只依据下方甲、乙、丙三份材料，列出三条主要结论。

每条结论保留适用日期、对象和必要条件，并标注来源条款编号。
材料没有的信息写“资料未说明”；不要使用材料之外的制度补全结论。

验收要求：结论与条款对应，条件完整，购买退货与租用归还分开；
“可以申请”不写成“已经批准”或“退款已经完成”。

材料：在这里提供甲、乙、丙的完整原文。
```

最后一行是模板中的输入位置。实际使用时，要把完整材料放进去；只写三个材料名称，不能证明模型已经看到了内容。

这条提示规定了任务、材料、输出和验收，但没有要求提交申请、调用外部服务或操作账号。它是一项整理工作。

### 整理出的结论应该能回到原文

下面是一组依据已给材料写出的教学整理结果，没有运行真实模型：

1. 在甲的生效期间，购买设备须在签收后第 0—7 天且未拆封，凭纸质发票申请退货；电子订单截图不能替代纸质发票。依据甲1、甲2。
2. 从 2025-06-01 起，乙替代甲的购买规则：第 0—14 天且未拆封可申请退货，凭证允许纸质发票或含订单号的电子凭证，聊天截图不合格；已拆封不能按乙1申请，只能转维修核验。依据乙1、乙2、乙3。材料没有说明已经批准退款。
3. 丙从 2025-06-10 起规定租用设备在签收后第 0—30 天归还，不适用于购买设备退货，也不修改乙的购买规则。依据丙1、丙2。

这三条的价值在于，读者能拿每条结论回到对应条款，检查条件是否保留。**出处要支持结论，不能只放一个看起来相关的编号**。

## 三、从整理资料继续到回答问题

现在材料保持不变，任务换成课程的主问题：

> 2025-06-12 提出申请，购买设备签收第 10 天，未拆封，有含订单号的电子凭证，能申请退货吗？

“帮我处理退货”仍然太宽泛。“处理”可能包含回答规则、填写草稿或实际提交，任务目标和行动范围尚未分开。

本例先明确只做问答：

```text
只依据甲、乙、丙的完整材料，回答下面的问题，不执行外部操作。

问题：2025-06-12提出申请，购买设备签收第10天，未拆封，
有含订单号的电子凭证，能申请退货吗？

按申请日期和购买／租用对象选择适用规则，
逐项核对天数、拆封状态和凭证。

输出：结论；逐项依据及条款编号；资料未说明或尚缺的信息。

验收：每项依据与用户事实对应；只说材料支持的结论；
“可以申请”不写成“退款已经完成”。
```

这条要求没有增加新制度，只是把已有规则怎样用于这个问题写清楚。

### 每个事实，分别在哪里起作用？

| 已提供的事实 | 怎样核对 | 依据 |
| --- | --- | --- |
| 申请日期为 2025-06-12 | 乙已从 2025-06-01 起生效，甲的生效期已结束 | 材料甲、乙的生效说明 |
| 对象是购买设备 | 使用购买退货规则，丙的租用归还规则不适用 | 乙1、丙2 |
| 签收第 10 天 | 在乙1的第 0—14 天范围内 | 乙1 |
| 未拆封 | 满足乙1的拆封条件 | 乙1 |
| 有含订单号的电子凭证 | 属于乙2允许的凭证类型 | 乙2 |

合起来，材料支持的结论是：

> 按乙1、乙2，已提供的事实满足教学材料中的退货申请条件，可以申请。这里仅做规则问答，未执行退货或退款；材料与题目没有提供审批或退款完成的结果。

这个回答把“条件成立”和“动作已完成”分开。反过来，如果回答“可以在 30 天内退货”，就是把丙1的租用归还搬到了购买退货上；即使它引用了丙1，仍然不合格。

**有数字、有出处，还要检查对象和适用条件是否匹配**。这也是提示里写“逐项依据”的原因。

### 提示明确，不等于结果自动合格

表达清楚可以给模型更明确的工作依据，但模型仍可能选错条款、漏掉否定或夸大结论。提示是一份要求，验收是核对实际结果；不能因为前者写得完整，就跳过后者。[^工程]

本课先建立这种检查方式，后面的第 16 课再把它整理为系统的评估标准。

## 四、缺少必要信息，就把缺哪一项说具体

沿用主问题，只删掉“未拆封”：

> 2025-06-12 提出申请，购买设备签收第 10 天，有含订单号的电子凭证，能申请退货吗？

申请日期、对象、天数和凭证都已给出，但拆封状态没有给。

乙1要求未拆封；乙3又明确，已拆封设备不能按乙1申请退货。这个条件会改变结论，因此不能从“设备已购买”“凭证齐全”推断它未拆封。

在这个变式中，可以回答：

> 资料不足，尚缺设备是否拆封的信息。日期、购买对象、签收天数和凭证与乙规则相符，但乙1要求未拆封，乙3排除已拆封设备按乙1申请。需要补充拆封状态，才能判断是否满足本次申请条件。

这个答案没有把缺信息当成“已拆封”，也没有硬说“可以申请”。它把已确认的部分和还缺的必要条件分开了。

### 缺用户事实与缺规则，是两类缺口

| 当前缺少什么 | 本例会怎样表现 | 应怎样说明 |
| --- | --- | --- |
| 用户事实 | 没说是否拆封 | 指出缺少拆封状态，并说明乙1、乙3为什么需要它 |
| 材料中的规则 | 问第 16 天是否可以获得特殊批准，材料没有给特批条款 | 说明乙1只支持第 0—14 天的申请条件，材料未说明特批规则 |

第二种情形也不能把“材料未说明特批”扩大成“现实中绝对没有特批”。本课只依据这组已给材料判断。

因此，**缺项应指出对象和理由，而不是只写一个笼统的信息不全**。读者知道缺的是什么，才知道下一步该补事实还是补来源。

## 五、角色说明、事实依据和动作授权，各负责什么？

在提示开头写“你是一位专家”，可以表达希望模型采用的回答视角或语言风格，但它没有新增甲、乙、丙的条款，也没有补上用户的拆封状态。[^工程]

对于同一条退货问题，下面三类内容需要分别看：

| 内容 | 负责什么 | 不能单凭它确认什么 |
| --- | --- | --- |
| 角色说明：“用规则审核人员的视角回答” | 说明回答视角与组织方式 | 用户未提供的事实、材料中没有的制度 |
| 事实依据：乙1、乙2以及题目给定事实 | 支持这次条件核对与有限结论 | 已经批准或已经退款 |
| 动作授权：有权来源允许对明确对象执行明确动作 | 说明真实操作允许到什么范围 | 动作已成功完成，或其他未授权操作也被允许 |

“乙1允许申请”是一条规则，不是替用户登录账号、提交申请或执行退款的授权。“你是专家”是一种角色说明，也不是获得这些权限的方式。

如果以后任务确实包含执行动作，就要明确对象、动作及允许范围，并在真实结果上验收。怎样校验与执行这些要求，是后续工具和 Agent 课程的内容；本例只做材料整理与规则问答。

### 强烈语气不会替代证据或执行检查

“必须给我肯定答案”改变不了缺少拆封状态的事实。“绝对不能出错”也不能代替检查结论是否被原文支持。

同样，在提示里写“不执行外部操作”表达了本次任务边界；真实执行系统仍应通过权限与运行控制落实这一边界。**任务要求、执行授权和结果证明，要分别确认**。提示文本本身不保证硬权限或实际操作结果。[^课程]

## 六、先自己写，完成四个基础检查

四题对应本课的四项掌握目标。先写答案，再看下一节对照。

### 检查 1：把四个问题分开

回看第二节的三份材料整理提示，分别指出任务、输入材料、输出契约和验收标准。

如果结果已经有三条结论，每条也附了编号，为什么仍需要读对应条款？

### 检查 2：改写一条含糊要求

材料仍使用本文完整的甲、乙、丙。要求只有“请整理一下这些规则”。

写一条可由别人替换材料后复用的提示，明确材料范围、需要保留的内容、出处和缺项处理，再写两项可直接检查的验收标准。

这里的复用是指保留任务结构，重新核对新材料；不能把甲、乙、丙的结论固定搬到其他制度上。

### 检查 3：删掉一个必要事实

沿用主问题，保留申请日期、购买对象、签收第 10 天和含订单号的电子凭证，删除拆封状态。

写出材料能支持的回答，并指出具体缺什么、哪两条规定使这个缺项影响结论。能否直接判定设备已拆封？

### 检查 4：辨认角色、证据与权限

有人把“你是退货专家”“按乙1、乙2可申请”连在一起，就声称“退款已经完成”。

请分别说明这三句话属于角色说明、条件结论还是结果声明，并指出前两句为什么不能证明最后一句。若本次任务只允许问答，可以据此执行退款吗？

## 七、参考答案与过关点

### 检查 1 的答案

| 项目 | 本例中的内容 |
| --- | --- |
| 任务 | 整理规则，提炼主要结论并保留适用条件 |
| 输入材料 | 当前实际提供的甲、乙、丙完整文本 |
| 输出契约 | 三条结论，每条含条件和条款编号，缺少的信息说明出来 |
| 验收 | 条款支持对应结论，日期和对象适用，条件完整，结论没有越过证据 |

数量与编号只证明形式上满足一部分要求。读原条款，才能确认引用支持、条件和结论是否一致。

**过关点**：四项各有明确内容，分清“长成什么样”与“凭什么合格”。

### 检查 2 的答案

一种合格写法是：

```text
请只依据下方材料整理主要规则。
按适用时间和对象归纳，保留必要条件与明确排除情形，注明来源条款。
材料未说明的信息直接写“资料未说明”，不补造制度或事实。

输出：主要结论及各自条件；对应条款；仍需补充的信息。
整理不包含提交申请、退款或其他外部操作。

材料：在这里提供完整文本。
```

对应的两项验收标准可以是：每条结论都能定位到支持它的原条款；整理后的条件和排除情形与原文一致，没有把购买与租用规则混在一起。

这题不要求和示例逐字相同，也不强制三条或表格；要求是任务、材料、输出和检查方式说清楚。

**过关点**：他人能理解该做什么、依据什么、交什么，并据提示检查结果；模板位置实际使用时填入完整材料。

### 检查 3 的答案

资料不足，缺少设备是否拆封。乙1要求未拆封，乙3排除已拆封设备按乙1申请，因此这一事实会改变判断。

其余已给条件可以逐项确认，但不能自行补上拆封状态，也不能把“没有说明”写成“已拆封”。应补充该事实后再判断完整申请条件。

**过关点**：具体指出缺项与对应条款，保留已确认内容，结论没有跨过缺失条件。

### 检查 4 的答案

- “你是退货专家”是角色说明。
- “按乙1、乙2可申请”是在给定事实满足条件时成立的规则结论。
- “退款已经完成”是对实际操作结果的声明，需要真实结果证明。

角色说明没有产生用户事实或操作权限；可以申请也不代表审批和退款完成。本次只有问答范围，不能据两句话把任务扩大成执行退款。

**过关点**：角色、证据、授权和结果各自定位，不用其中一项替代另一项。

### 怎样确认已经掌握？

能独立完成四题，并能在材料或用户事实变化后重新核对，就覆盖了本课的四项基础要求。出现卡点时，可以按下表回读：

| 卡点 | 回读位置 |
| --- | --- |
| 任务、格式和验收总混在一起 | 第一节的四个问题及输出与验收区别 |
| 要求仍然只是“整理一下” | 第二节的逐步补齐与示范提示 |
| 知道信息不全，却说不清具体缺项 | 第四节的用户事实与规则缺口 |
| 把专家身份或可申请当成真实操作完成 | 第五节的角色、证据与授权分工 |

文章与练习提供达标路径，实际掌握仍以独立作答为准。

## 八、可选进阶：让稳定要求与本次材料分开

如果经常做同一类整理，可以保留任务要求与验收方式，每次替换输入材料和问题。这样复用的是处理方式，而不是固定答案。[^提示]

例如，将第三节的问答提示分成四段：

```text
任务与边界：只回答给定问题，不执行外部操作。
本次材料：实际提供的完整条款与版本说明。
本次问题：日期、对象、天数、状态和凭证等已知事实。
输出与验收：有限结论、逐项条款、具体缺项，并回原文核对。
```

材料换了，适用条件和结论都要重新判断。“退货申请条件”也不能默认搬到其他主题，需要重新确定那个任务依赖哪些事实。

分段、标题或结构化标记可以帮助区分输入内容；使用哪种格式，应由实际任务和接口需要决定。它们没有自动核实材料，也没有赋予执行权限。[^工程]

对于简单的翻译或短文本改写，一句完整指令可能已经够用。本课的原则是把必要要求说清楚，而不是把每次任务都扩成很长的模板。

## 带着明确任务进入下一课

现在你可以从四个方向检查一条要求：做什么、依据什么、交什么、怎样判断合格。遇到信息不足时，指出具体缺项；遇到角色和动作描述时，分别检查事实与授权。

第 08 课会在明确规则之后，用正确示例进一步说明输出模式；第 09 课再讨论怎样把较大的工作拆成可检查的步骤。新增方法都要服务于当前任务，已经缺少的事实仍然需要相应材料。

**先写清任务和验收，结果才有可以核对的标准**。模型是否实际做到了，仍要回到它交付的内容与依据上检查。
